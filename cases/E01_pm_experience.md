# Case Study: GT-SS500 PM 경험 — APQP 기반 양산 진입

> 프로젝트: PLUVA FRIEND SS500 (GT-SS500)
> 역할: 모터제어 개발자(본업) + 주니어 PM(겸임)
> 기간: 2025 ~ 2026 (양산 진입 단계)
> 결과: APQP Phase 2~3 운영, 이슈 37건+ 관리, 132개 부품 BOM, J-Agri 2025 출품, 양산 16pcs + Spare 4pcs 준비

---

## 한 줄 요약

선임연구원이 본업(모터제어)과 PM 겸임을 동시 수행하면서, **개발 프로세스 자체를 정량화·체계화**해서 양산 진입을 받쳐낸 경험.

---

## 배경 — 왜 PM 겸임이었나

SS500은 기술적으로는 **CAN 기반 분산 제어 시스템**(VCU + 구동모터 ×2 + 팬모터 + 펌프 + BMS, 5개 CAN 노드)이지만, 사업적으로는 **국내외 부품 업체 다수가 동시 참여하는 양산 프로젝트**입니다.

엔지니어 입장에서 "기술만 잘 하면 된다"가 통하지 않는 순간이 있었습니다:
- 배터리 업체가 ROM을 임의 변경 → CAN 정합성 깨짐
- 부품 132개 중 23건 재고 미확보 → 양산 일정 위협
- J-Agri 2025 출품용 샘플 기일 → 5개 부서 동시 조율 필요

**기술 이슈와 PM 이슈는 분리되어 있지 않습니다.** 그래서 본업을 유지하면서 PM 역할을 자연스럽게 흡수했고, 그 과정에서 다음 4가지 영역을 경험했습니다.

---

## 1. APQP — Phase 2~3 운영

자동차 Tier-1에서 익힌 APQP(Advanced Product Quality Planning)를 농기계 양산에 적용했습니다.

| Phase | 활동 | 산출물 |
|-------|------|--------|
| Phase 2 (Product Design) | DFMEA 작성, DRBFM 검토 | DFMEA 문서, 위험 우선순위(RPN) 테이블 |
| Phase 3 (Process Design) | 금형 발주, 양산 초도품 BOM 관리 | BOM V0.3.4, 금형 발주 일정 |
| Phase 3 → 4 전환 | Alpha 1~3호기 검증, Pilot 2~4호기 검증 | 검증 리포트, 이슈 #72/#78/#000 |

**핵심 원칙**: APQP는 "문서를 만드는 일"이 아니라 "위험을 사전에 정량화하는 도구". DFMEA의 각 항목이 실제 검증 시험과 연결되어야 한다.

**구체적 사례** — DFMEA에서 "배터리 보호로직 미작동"을 RPN 상위로 분류 → 1차/2차/3차 검증으로 연결 → SOC 162.4% 오버플로우 발견 (D2 케이스 참조).

## 2. 이슈 트래킹 — 37건+ Notion DB 운영

### 운영 방식

```
이슈 발생
  ↓
Notion DB 등록 (10개 카테고리 분류)
  ↓
담당 부서 배정 (전력제어/융합제어/H&I/품질)
  ↓
주간 회의에서 우선순위 재조정
  ↓
완료 후 검증 → 클로즈
```

### 분류 카테고리 (10개)

| 카테고리 | 예시 |
|---------|------|
| 배터리/BMS | SOC 오버플로우, 셀 편차 |
| 모터제어 | 펌프 파워 부족, 팬모터 진동 |
| CAN 통신 | 종단저항 누락, ROM 버전 불일치 |
| 안전 시스템 | 범퍼 정지거리, 비상정지 시퀀스 |
| 전력 시스템 | Main Relay 소손, Power Hold |
| 자율주행 | RTK GPS 정밀도, 경로 추종 |
| 기구/내구 | 솔레노이드 동파, 오링 가공불량 |
| 양산/품질 | 부품 재고, 협력사 품질 |
| 펌웨어 | OTA 업데이트, Init 루틴 |
| 기타 | — |

### 본인 담당 — 대표 사례

> 건수보다 **어떤 이슈를 어떻게 풀었는지**가 더 중요하다.

**전력제어 단독 발행/검증**
- **배터리 BMS 정합성** — SOC 162.4% 오버플로우, 셀 편차 260mV 미감지를 CAN 로그 분석으로 발견 (D2)
- **펌프 파워 분석** — 0.96kW → 3.23kW 전력 예산 / 비용 3배 증가 / 운전시간 반감 트레이드오프 정량화 (D4)
- **동파 RCA** — 5호기 동시 발생 → 솔레노이드 오링 가공불량(depth+wall thickness) 근본원인 추적 → 20개 발주 + 설계변경 (D1)

**전력제어 공동 (융합제어 / 품질팀과)**
- **상태머신 제어권 전환** — RC/LCD/ADT 3모드 / NONE 상태 삭제로 안전 버그 해결 (D3)
- **Main Relay 안전 시퀀스** — 소손 → "VCU 정지 → 5분 후 MR 차단" 안전 시퀀스 재설계 (D1)
- **CAN DB 4종 관리** — VCU↔모터컨트롤러↔BMS↔팬 정합성 검증 (D1)

## 3. BOM·부품 관리 — 132개 부품 / 양산 16pcs

### BOM V0.3.4 — 132개 부품 관리

- 카테고리별 분류: 전장(VCU/모터컨트롤러/BMS/충전기), 기계(샤시/펌프/탱크), 소모품
- 각 부품: 품번 / 사양 / 공급사 / 단가 / 리드타임 / 재고
- **재고 미확보 23건 식별** → 발주 우선순위 재조정

### 부품 서베이 — 국내/해외

| 영역 | 활동 |
|------|------|
| 국내 | 솔레노이드/오링 업체 재발주 (20개), 양산 협력사 품질 관리 |
| 중국 | 모터/배터리 부품 서베이, 가격·리드타임 비교 |
| 일본 | J-Agri 2025 전시 후 협력 가능 업체 미팅 |

### 양산 계획

- **양산 16pcs + 대차/Spare 4pcs** = 20pcs 생산 계획
- Alpha 1~3호기 (개발) → Pilot 2~4호기 (검증) → 양산 (16+4)

## 4. 글로벌 협업 — J-Agri 2025 출품

일본 J-Agri 2025 전시회 출품을 위해 **5개 부서 조율**을 PM으로서 수행했습니다.

### 일정 압박

```
출품 기일 (확정)
  ↓ -8주
샘플 사양 동결
  ↓ -6주
기구 가공 시작
  ↓ -4주
펌웨어 freezing
  ↓ -2주
통합 시험
  ↓ -1주
선적 / 통관
  ↓
전시 (J-Agri 2025)
```

### 5개 부서

| 부서 | 담당 |
|------|------|
| 전력제어 | 모터/배터리/CAN 펌웨어 freezing |
| 융합제어 | VCU 통합 / 자율주행 |
| H&I | 기구 / 외관 / 데칼 |
| 품질 | 시험 / 검증 |
| 영업/사업 | 일본 통관 / 현지 대응 |

### 결과

기일 내 샘플 출품 성공. **타사 농기계 대비 기술 차별점**(자율주행, CAN 분산 제어)을 일본 시장에 소개.

## 5. PM이 실제로 한 일 — 본업과의 시너지

본업이 모터제어 개발이라서 PM 역할에서 **"기술 이슈를 즉시 판단할 수 있는 PM"** 포지션이 가능했습니다.

| 상황 | 일반 PM | 기술 PM (본인) |
|------|---------|----------------|
| 배터리 업체가 "ROM 수정했다" | "수정 완료로 마킹" | **CAN 로그 분석 → 실측 검증 → 미해결 항목 재요구** |
| 펌프 파워 부족 클레임 | "전력제어팀에 전달" | **0.96kW → 3.23kW 전력 예산 분석 → 비용·시간 트레이드오프 정량화** |
| 부품 사양 변경 요청 | "엔지니어 회신 대기" | **Init 루틴 호환성 검토 → 즉시 OK/NG 회신** |

→ "전달자 PM"이 아니라 "**판단자 PM**"으로 일했습니다.

## 면접 예상 Q&A

**Q: 본업과 PM 겸임이 부담되지 않았나요?**

> 처음에는 부담스러웠지만, **기술 이슈와 PM 이슈는 분리되어 있지 않다**는 것을 깨닫고 나서는 오히려 효율이 올라갔습니다. 배터리 업체와의 협의에서 "ROM을 수정했는지"를 PM이 판단하려면 결국 엔지니어에게 물어봐야 하고, 그 대기 시간이 곧 일정 지연이었습니다. 본업을 하면서 PM 역할을 흡수하니 의사결정 사이클이 짧아졌습니다.

**Q: APQP가 농기계에 정말 필요한가요?**

> 네. 농기계는 사용자가 비전문가(농민)이고, 사용 환경이 가혹하며(흙·물·진동), 사고 시 인명 위험이 있습니다. 자동차 Tier-1 수준의 품질 시스템이 필요한 영역인데, 농기계 업계는 아직 그 수준이 아닙니다. APQP를 도입한 것은 "정석을 따른 것"이고, 실제로 양산 전 보호로직 미작동을 발견하는 등 효과를 봤습니다.

**Q: 가장 어려웠던 PM 이슈는?**

> 가장 어려웠던 것은 **명확한 문제점과 요구사항을 도출하는 일**이었습니다. 현장에서 올라오는 이슈는 대부분 모호한 형태입니다 — "펌프가 약하다", "배터리가 이상하다", "양산 일정이 빠듯하다". 이걸 그대로 두면 부서 간 핑퐁이 됩니다.
>
> 저는 매 이슈에서 다음 3가지를 먼저 확정하려고 했습니다:
> 1. **문제의 정량적 정의** — "약하다"가 아니라 "현재 0.96kW, 타겟 3.23kW"
> 2. **요구사항의 출처** — 누가 / 왜 이 요구를 했는가
> 3. **합격/불합격 기준** — 어떤 데이터를 보면 끝났다고 말할 수 있는가
>
> 이 3가지가 안 정해진 상태에서 부서 회의에 들어가면, 시간만 쓰고 결론이 안 납니다. 반대로 이 3가지가 명확하면, 의사결정이 빨라지고 업체 협의도 데이터 기반으로 진행됩니다 (D2 배터리 정합성 케이스 참조).
>
