문제

하드웨어 시간은 비싸고 한정되어 있다. 제어 로직·보호 기능·경로 추종을 바꿀 때마다 실물을 돌리면 검증이 개발을 막는다. 개인 시간에, 일반적인 스키드 스티어 차량 모델을 바탕으로 한 시뮬레이터를 만들어 실물에 올리기 전에 깨질 것을 먼저 깨뜨리는 환경을 갖추려 했다.

역할

전 구간 단독 — 물리 모델 · CAN 코덱 · 보호로직 · 센서 퓨전 · 경로 계획 · ROS2 패키지 · 테스트 · CI.

결과

Level-2 물리 시뮬레이션(뉴턴 역학 + Bekker 지면 + 센서 노이즈) 위에 테스트 497개가 매 커밋마다 돈다

구동 드라이버 보호기능을 고장모드로 모델링해 시나리오에서 재현

시뮬레이션이 대신하지 못하는 항목을 구분해 기록 — 모델 결과는 모델 결과로만 쓴다

아키텍처 — 순수 Python 코어 위에 ROS2

알고리즘은 ad_core에 ROS2 비의존 순수 Python으로 두고, ROS2 패키지는 그 위의 얇은 어댑터다. 그래서 코어 테스트 331개는 ROS2 없이 CI에서 돌고, Gazebo·Nav2 통합은 로컬에서만 검증한다.

보호기능을 고장모드로 모델링한다

구동 드라이버의 소프트 퓨즈(정격 기준)와 열 보호(온도 임계)를 시뮬레이션에 넣었다. 과부하 구간에서 퓨즈가 먼저 트립하고, 온도는 그 뒤에도 관성으로 오른 뒤 식는다 — "전류를 끊었는데 왜 온도 알람이 뒤늦게 뜨나"를 실물에서 겪기 전에 시뮬레이션이 먼저 보여준다.

시나리오 스윕 — 어떤 스트레스 인자가 중요한지 먼저 가려낸다

scenario_runner가 직진·S커브·급선회 3개 미션을 5개 지형(마른 흙·젖은 흙·자갈·경사 등)에서 자동 실행해 CTE·슬립·정착 시간을 비교하고, module_test_report가 구동계·지면·동역학·센서 노이즈 블록별로 파라미터 감도를 스윕해 Markdown 리포트로 낸다. 가속 시험을 설계할 때 스트레스 인자를 고르는 것과 같은 논리 — 스윕으로 민감한 인자를 찾고, 실물 시간은 거기에만 쓴다.

시뮬레이션이 대신하지 못하는 것

이 스택은 개인 프로젝트이며 실물과의 일치를 주장하지 않는다. 지면 모델(Bekker) · 센서 노이즈 · 구동계 지연은 가정 파라미터이고, 결과는 모델 결과로만 표기한다. 대신하지 못하는 항목을 구분해 두는 것이 이 프로젝트의 검증 원칙이다.

방법의 연결

"이 보호로직이 어느 조건에서 먼저 걸리는가"라는 질문을 시뮬레이션으로 먼저 답해 보는 프로젝트다. 다이나모미터 벤치가 모터 단품의 실물 시험대라면, 이 시뮬레이터는 차량 한 대 단위의 오프라인 모델 검증 환경이다.
