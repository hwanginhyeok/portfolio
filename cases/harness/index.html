AI 하네스AI Harness

업무 생각나는거 소통하면서 일하고 싶어서I wanted to work by talking through whatever work came to mind.

"작업이 완성됐는지 안됐는지 알수가 없네.""I can't tell whether the work is done or not."

문제Problem

AI에게 일을 시켜 놓고도 끝났는지, 믿어도 되는지 알 수 없었다. 한 모델에 몰아 쓰면 구독 한도가 먼저 바닥나 일이 멈춘다.I could give AI a job but not tell whether it was done or whether to trust it. Leaning on one model drains its quota first and the work stops.

구조와 실제 화면Structure and real screens

핵심 판단 — 문제 → 선택 → 이유Key judgements — problem → choice → why

  1. 비싼 모델만 쓰다 구독 한도가 먼저 바닥난다Using only the priciest model drains the subscription first 모든 일에 가장 센 모델을 쓰면 주간 한도가 일찍 떨어져 PM 세션이 멈춘다.Running every job on the strongest model burns the weekly quota early and the PM session stops. → 일을 위험도(높음·보통·낮음)로 나누고, 계정마다 한도가 곧 풀리는 순서로 모델을 고른다. PM 몫 20%는 남겨 둔다.Split jobs by risk (high, medium, low) and pick models in the order their quota resets soonest. Keep 20% for the PM. → 싼 모델로 될 일에 비싼 한도를 쓰지 않는다. 버려질 한도부터 쓴다.Cheap jobs never spend expensive quota, and quota about to expire is used first.
  2. 워커 여럿이 한 저장소를 건드리면 코드가 꼬인다Several workers in one repository tangle the code 여러 AI가 같은 저장소를 동시에 고치면 브랜치가 섞이고 충돌이 난다.Many AIs editing the same repository at once mix branches and cause conflicts. → 워커마다 따로 작업 폴더와 브랜치를 주고, 합치는 일은 PM만 한다. 워커는 스스로 합치지 못한다.Give every worker its own working folder and branch. Only the PM merges; a worker cannot merge its own work. → 워커가 잘못해도 본 코드는 그대로다. 되돌리기도 쉽다.A bad worker leaves the main code untouched, and undoing is easy.
  3. 눌러선 안 될 버튼을 AI가 잘못 누른다The AI presses a button it should not 웹 화면에서 버튼을 고르는 일에 작은 자체 모델을 쓰는데, 틀리면 되돌릴 수 없는 버튼도 있다.A small own model picks buttons on web pages, and some buttons cannot be undone if it is wrong. → 되돌릴 수 없는 버튼은 모델이 고른 글자가 기대한 글자와 같을 때만 누른다. 아니면 정해 둔 방식으로 돌아간다.An irreversible button is pressed only when the label the model chose equals the expected label; otherwise it falls back to a fixed routine. → 모델은 빠르게 쓰되, 사고는 막는다.Use the model for speed, but block the accident.
