## 3. 정직 기재 원칙 — 이번에 새로 긋는 선

- **과소 기재도 오기재다.** rs500을 "학습 단계"로 두는 것은 497개 테스트를 지우는 것이다.
- **회사 자산은 Q5 답 전에 쓰지 않는다.** HIH_2의 fleet-ops·텔레메트리는 본인 작업임이 확인되고
  공개 범위가 정해진 뒤에만 Tier 1에 올린다.
- **"없음" 열은 없음으로 둔다.** UDS·ISO 26262·ASPICE·QNX·400V 트랙션 — 배우는 중이라고 쓸
  증거가 생기기 전까지 이력서에 올리지 않는다. 배우면 `knowledge-base`에 노트가 생기고, 그게 증거다.
- **숫자는 실측만.** 이 문서의 모든 커밋 수·태스크 수·테스트 수는 2026-09-06 실측이며
  `ACTIVITY_INVENTORY.md`에 출처가 있다.

## 5. ⑤ 전문지식 배양 — 우선순위

`ACTIVITY_INVENTORY.md §5`의 "없음" 열을 **지원 타깃이 요구하는 순서**로 정렬한 것.
각 항목은 `knowledge-base`에 노트가 생기고 사람 검증(✅)이 붙으면 "학습 중"으로 이동한다.

| 순위 | 항목 | 요구한 타깃 | 첫 산출물 |
|:---:|---|---|---|
| 1 | **UDS (ISO 14229)** — 진단 서비스 계층 | Tesla FSE | `knowledge-base/automotive/uds.md` + CAN 위에 UDS 요청/응답 파서 (rs500 `md2k_codec` 옆에) |
| 2 | **ISO 26262 · ASPICE** — 기능안전·프로세스 | NVIDIA, 완성차 Tier-1 전반 | DFMEA → ISO 26262 Part 3/4 매핑 표 1장, SS500 상태머신을 ASIL 관점으로 재기술 |
| 3 | **고전압 안전** — HV 인터록·절연저항·LOTO | Tesla, EV 전반 | 노트 1건. 실습 증거는 회사 과제 없이는 어렵다 — 정직하게 "개념" 수준 |
| 4 | **ISO 21448 (SOTIF)** | NVIDIA, AV | 노트 1건 + rs500 시나리오 러너에 SOTIF 트리거 조건 반영 |
| 5 | FlexRay · Automotive Ethernet | NVIDIA Vehicle Integration | 노트 1건 |

## 6. ⑥ 직접 프로젝트 — 갭을 메우는 것만

"무언가 만들어보기"는 **§5의 갭에 증거를 붙이는 프로젝트**로 한정한다. 흥미로 시작하는 프로젝트는
포트폴리오에 오르지 못하고, 이미 26개 저장소가 그걸 증명한다.

| 후보 | 메우는 갭 | 크기 | 포트폴리오 위치 |
|---|---|---|---|
| **rs500에 UDS 진단 레이어 추가** — MD2K CAN 위에 UDS 서비스(0x22/0x2E/0x19) 시뮬 + 테스트 | UDS (Tesla) | 2~3주 | `cases/autonomy-stack/` 하위 절 |
| **rs500 시나리오 러너에 안전 시나리오** — SOTIF 트리거(센서 노이즈·지면 급변) → 페일세이프 상태머신 검증 | ISO 21448, Functional Safety | 2주 | 같은 케이스 |
| **다이나모 벤치를 HIL 문서로 재구성** — 기존 데이터·회로도로 HIL 아키텍처 1장 | HIL 어휘 (Physical AI) | 3일 | Track B |
| **fleet 텔레메트리 → 필드 고장 트렌드 리포트** (🟡 Q5) | Tesla FSE "fleet 데이터 분석" | Q5 뒤 | Tier 1 |

**하지 않을 것**: 새 서비스·봇·콘텐츠 파이프라인. Tier 4는 이미 충분하다.
