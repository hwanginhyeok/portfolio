## §0. 본 문서의 역할

B1이 "있는 패"를 나열했다면, B2는 **"누구에게 어떤 메시지를 보내고, 어떤 패를 그 증거로 쓸 것인가"**를 결정한다.

B2가 비어 있으면 B3(배치)에서 다시 흔들린다. v1→v2→v3 반복의 원인.

**B2 산출물**:
1. 타겟 회사·JD 키워드 (사용자 입력 필요)
2. 확정된 핵심 메시지 3~5개
3. 자산 × 메시지 매트릭스 (자산을 어디에 쓸지)
4. 채널별 자산 매트릭스 (이력서·포폴·면접·링크드인)
5. 컷 리스트 (안 쓸 자산 + 사유)
6. B3·B4로 넘기는 결정사항

### 2.3 메시지 충돌 점검 (사용자 결정 후)

확정 메시지 사이의 **충돌 가능성** 사전 점검:
- "PM 풀사이클(MC-B)" + "AI 워크플로우(MC-E)" → 동시 강조 시 "PM이 본업인가, AI가 본업인가" 모호. 서열 명확화 필요.
- "분야 무관(MC-F)" + "특정 깊이(MC-A 또는 MC-D)" → "넓은가 깊은가" 메시지 충돌. **둘 다 한다**는 프레임으로 묶어야 함.
- "정직 기재 특허(MC-H)" → 다른 메시지 어디에도 안 묶이면 단독 약함. 보통 §3.1 패턴 신뢰도 보조로 사용.
