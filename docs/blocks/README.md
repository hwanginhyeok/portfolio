# 포트폴리오 4블록 워크플로우

> **원칙**: 순서 엄수. 블록을 건너뛰면 다시 엎는다.
> v1→v2→v3 반복의 원인은 블록 2(활용 전략) 없이 바로 블록 3(배치)로 넘어간 것.

## 블록 의존성

```
[B1] 자료 인벤토리   →   [B2] 활용 전략     →   [B3] 배치       →   [B4] 디자인
    WHAT HAVE             HOW TO USE             WHERE TO PUT         HOW IT LOOKS
    (있는 패)              (증거 매칭)            (와이어프레임)       (코드/비주얼)
```

## 블록 요약

| # | 블록 | 질문 | 산출물 | 상태 |
|---|------|------|--------|------|
| B1 | [자료 인벤토리](01-inventory/) | 어떤 자료를 쓸지 | `INVENTORY.md` | ⬜ |
| B2 | [활용 전략](02-usage/) | 그 자료를 어떻게 활용할지 | `USAGE_STRATEGY.md` | ⬜ |
| B3 | [배치](03-layout/) | 어떻게 홈페이지에 배치할지 | `LAYOUT.md` | ⬜ |
| B4 | [디자인](04-design/) | 어떻게 디자인할지 | `DESIGN_SYSTEM.md` + astro 페이지 | ⬜ |

## 블록 밖 (부가)

- **B5 부가자료**: 이력서, GitHub 프로필, 영문 버전 — 포트폴리오 본체 완성 후

## 게이트 규칙

- **B1 완료 게이트**: 모든 자산이 INVENTORY에 등록되고 품질 등급(A/B/C)이 매겨짐
- **B2 완료 게이트**: 각 자산이 "어떤 메시지의 증거인가"가 명시됨. 컷 리스트 확정
- **B3 완료 게이트**: 5섹션 × 섹션 내 순서 확정. 페이지 이동 경로 확정
- **B4 완료 게이트**: astro 페이지가 실제로 배포 가능한 상태
