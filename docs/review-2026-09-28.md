## 1. Project Purpose & System Architecture

`portfolio` (directory `포트폴리오` on server-pc, GitHub repository `portfolio`) serves two primary functions:
1. **Interactive Engineering Portfolio Website**: An Astro-powered static web platform showcasing career history, physical AI & embedded systems case studies, system architecture diagrams, patent details, and interactive Observable Plot data visualizations.
2. **Automated Job Intelligence & Application Tracking System**: An autonomous crawling, scoring, reporting, and calendar synchronization pipeline that monitors tech recruitment boards (Jasoseol, Wanted, Global ATS like Workday/Greenhouse), filters roles matching Hwang Inhyeok's profile (Robotics, HW/SW/Embedded, Power Electronics, Test & Reliability Engineering), pushes daily curated HTML summaries to Telegram, and tracks active company application materials.

The codebase consists of four functional layers:

### Layer 1: Astro Static Portfolio Web Application (`src/`, `public/`)
- **Role**: Modern, performant static portfolio site with dark-mode responsive styling.
- **Components**:
  - `src/pages/index.astro`: Main portfolio landing page with interactive timeline, engineering domains, and project highlights.
  - `src/pages/cases/`: In-depth engineering case studies (SS500 MBD, EOP 400W motor pump, Autonomy Stack, Production Validation, Patent analysis).
  - `src/components/`: Reusable UI components (header, footer, case cards, plot charts, navigation).
  - `astro.config.mjs`, `tailwind.config.mjs`: Astro 6.x build configuration and Tailwind CSS styling.

### Layer 2: Job Board Collectors & Data Ingestion (`scripts/`)
- **Role**: Automated web scraping and API ingestion engines collecting job postings into structured Markdown and JSON staging inboxes.
- **Components**:
  - `scripts/jasoseol_collect.py`: Ingests experienced job announcements from Jasoseol (자소설닷컴) recruitment calendar API into `docs/jd/_inbox/jasoseol/{id}.md`, backed by state tracking in `state.json`.
  - `scripts/wanted_collect.py`: Pulls Korean tech postings from Wanted API into `docs/jd/_inbox/wanted/{id}-{company}.md`, evaluates candidate domain fit, and updates state.
  - `scripts/wanted_state_repair.py`: Verifies, repairs, and deduplicates the Wanted `state.json` ledger.
  - `scripts/global_collect.py`: Ingests foreign multinational postings from enterprise ATS endpoints (Workday, Greenhouse, Lever for Aptiv, Tesla, Apple, Applied Materials, Shield AI) into `docs/jd/_inbox/global/`.
  - `scripts/shortlist.py`: Candidate evaluation engine applying strict owner-domain filters, feasibility gates (work authorization, ITAR, location), and ranking logic.

### Layer 3: Reporting & Integration Delivery (`scripts/`)
- **Role**: Daily automated reporting, Telegram message dispatch, and calendar integration.
- **Components**:
  - `scripts/jasoseol_report.py`: Aggregates active actionable Jasoseol postings, generates standalone responsive HTML reports (`docs/jd/report/jasoseol-YYYY-MM-DD.html`), and sends attachments to Telegram.
  - `scripts/jasoseol_calendar.py`: Evaluates actionable posting deadlines and creates deadline events on Google Calendar using the `hih-schedule` CLI.
  - `scripts/applications_report.py`: Reads the single source of truth application ledger (`docs/jd/applications.json`), updates markdown view `docs/jd/APPLICATIONS.md`, and sends status reports via Telegram.

### Layer 4: Presentation Generators & Historical Previews (Root & `docs/archive/`)
- **Role**: Ad-hoc presentation deck generation and historical markdown preview builders.
- **Components**:
  - `generate_ppt.py`, `clean_grad_ppt.py`, `renew_grad_ppt.py`, `inspect_ppt.py`: python-pptx generation scripts that compile case studies into PPTX decks (`대학원_포트폴리오_황인혁.pptx`, etc.).
  - `build_preview.py`, `preview.html`: Pre-Astro static preview builder that rendered early markdown case studies from `cases/` and Mermaid diagrams from `diagrams/`.

## 6. Secrets Handling

### Current State
- The collector scripts read `PM_BOT_TOKEN` and `PM_BOT_CHAT_ID` by parsing `/home/window11/project-manager/.env`.
- No raw secret values or `.env` files are committed in the repository (properly gitignored).
- However, reading an external project's `.env` creates an undesirable coupling to the legacy `project-manager` directory.

### Target State under Project Standard
- All secret values remain in the macOS Keychain (`hih-secret`).
- Secret names are explicitly cataloged in `ops/ops.yaml`:
  - `PM_BOT_TOKEN`
  - `PM_BOT_CHAT_ID`
- When workloads migrate to macOS in Phase 2, scripts will receive secrets via environment variables or invoke `hih notify` directly, eliminating `.env` file dependencies.
