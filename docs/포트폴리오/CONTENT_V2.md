## 6. Field Episodes (현장 해결사)

### 6.1 섹션 타이틀
**분야 무관 — 문제가 있으면 파고든다**

> 코드·HW·기구·전력·SW. "내 분야"의 경계가 없다.
> 타부서와 협업해 원인을 찾고, 시험으로 증명하고, 대책까지 따라간다.

### 6.2 에피소드 4개 (배터리 제외, 전력/기구/안전 다양하게)

#### Episode 1 — **분사 성능 개선 (펌프 전력 분석)**
- **분야**: 전력 + 기구 + 경영 판단
- **문제**: 기성 모델 대비 유량 4배 부족. "펌프를 업그레이드해야 하나?"
- **분석**: 노즐 1.5mm × 19개 아세아텍 기준 역산 → 펌프 수동력 1.65kW → 모터 입력 3.23kW → 필요 전류 64A
- **트레이드오프 정량화**: 비용 30만원 → 130만원 (3배 증가), 운전시간 4h → 2h (반감)
- **결과**: 경영진이 정량적 데이터로 판단. "현 구성 유지 + 노즐/유로 최적화"로 방향 전환
- **배운 것**: 공학적 답이 "업그레이드 ○"이어도, 시스템 전체 트레이드오프로 보면 "○ 보류"가 정답일 수 있다.
- **Issue**: #60

#### Episode 2 — **펌프 신뢰성 — 동파 RCA (5호기 동시 발생)**
- **분야**: 기구 + 재료 + 품질
- **문제**: 5호기 동시에 동파 발생. 단순한 날씨 문제인가?
- **추적**: 솔레노이드 밸브 오링 상태 점검 → **오링 가공불량** 확인 (depth + wall thickness 규격 미달)
- **근본원인**: 오링이 완전 밀폐되지 못해 잔수 → 기온 강하 시 얼음 팽창 → 파손
- **대책**: 오링 20개 재발주 + **설계 변경** (depth/wall thickness 규격 재정의)
- **검증**: 동일 조건 재현 시험 → 재발 0
- **배운 것**: 환경(날씨)으로 설명 가능한 것부터 의심하지 말 것. 규격을 의심하라.

#### Episode 3 — **구동 신뢰성 — 범퍼 안전 시험 설계**
- **분야**: 전력 + 제어 + 안전
- **문제**: 자율주행 중 장애물 접촉 시 안전하게 멈추는가?
- **시험 기획**: 정지거리 / 상전류 피크 / 정착시간 3축으로 검증 체계 설계
- **벤치 구축**: 범퍼 접촉 시점 센싱 → 모터 전류 / 속도 / 정지거리 동기 측정
- **결과**:
  - 3km/h 주행 중 접촉 시 정지거리 **0.082m**
  - 상전류 피크 **308A**
  - 정착시간 **467ms**
- **후속**: Main Relay 소손 이슈 발견 → "VCU 정지 → 5분 후 MR 차단" 안전 시퀀스 재설계
- **배운 것**: 시험 설계가 곧 제품 사양이다. 측정할 수 없으면 스펙이 아니다.

#### Episode 4 — **제어권 상태머신 — 치명적 버그 제거 (Issue #79)**
- **분야**: FW + 시스템 안전
- **문제**: RC 모드 주행 중 리모콘 페어링 → LCD 모드 전환 → **속도 지령 없음에도 차량이 전진**
- **추적**: 모터 컨트롤러 상태머신이 이전 지령(3km/h)을 유지. LCD 모드는 속도 지령을 내보내지 않음.
- **근본원인**: NONE 상태의 존재 자체가 모호한 전환을 허용. 모드 전환 시 Init(속도 0) 루틴 누락.
- **대책**:
  - **NONE 상태 삭제**
  - 모든 Transition에 **Init 루틴** 강제 (속도 0 → 새 지령 수용)
  - RC / LCD / ADT 3모드로 간소화
- **결과**: 무인 전진 현상 재현 불가. 안전 검증 통과.
- **배운 것**: 상태가 많을수록 조합 폭발이 일어난다. 삭제가 최고의 최적화.

### 6.3 공통 메시지
> 네 에피소드가 각각 다른 분야(전력/기구/안전/FW)지만, **접근 방식은 같다**:
>
> 1. **현상**을 의심하지 않고, **원인**을 추적한다.
> 2. **가설**을 세우고, **시험**으로 증명한다.
> 3. **대책**은 설계 변경까지 간다. 증상 무마 X.
> 4. **분야 경계**를 넘는다. 내가 "전력제어 담당"이어도 기구가 문제면 기구를 판다.

## 7. 시험 — 기획·설계·증명·분석

### 7.1 섹션 타이틀
**시험으로 증명한다 — 기획/설계/증명/분석**

> 시험은 몇 개 만들었는가가 중요한 게 아니다.
> **매번 어떻게 접근하는가**가 역량이다.

### 7.2 4단계 프로세스

#### 1. 기획 (Plan)
**어떤 가설을 세우는가?**
- EOP: "SVPWM 절환이 FET 온도를 낮추는가?"
- SS500 범퍼: "3km/h 주행 중 장애물 접촉 시 정지거리는?"
- SS500 팬: "프로펠러 직경 변경이 풍속에 미치는 영향은?"

#### 2. 설계 (Design)
**장비가 없으면 만든다**
- 다이나모미터 토크제어 시스템 — 비선형성 0.008% 달성
- 팬 벤치 / 펌프 벤치 / 범퍼 시험대 직접 구축
- CAN 정합성 체크리스트 — 반복 검증 프로토콜 표준화

#### 3. 증명 (Prove)
**데이터로 답한다**
- FET 온도 1~6°C 저감 (2,932 데이터 포인트, PWM 온도 비교)
- 풍속 +57% (7.9 → 12.4 m/s, 20파이 프로펠러 채택 근거)
- 정지거리 0.082m, 피크 308A (자율주행 안전 확보)
- 극저온 기동 300초 → 100초 (-40°C 실증)

#### 4. 분석 (Analyze)
**데이터가 말하는 것 → 다음 결정**
- SVPWM 채택 결정 근거 제공 → 국책과제 완료
- 펌프 업그레이드 보류 (비용 3배 + 운전시간 반감 트레이드오프)
- 팬 20파이 프로펠러 채택 (+57% 정량 비교)
- 오링 설계 변경 (규격 재정의 후 재발 0)

### 7.3 섹션 하단 메시지
> 대학원에서 Ansys Maxwell → MATLAB/Simulink → 실험 검증으로 훈련된
> "**모델 → 시뮬레이션 → 실험**" 체질이, 실무의 "기획 → 설계 → 증명 → 분석"으로 이어진다.

- **야간 무인 실행** — cron 00:00 → tonight_prompt → 아침 브리핑

### 8.3 왜 두 가지 축인가 (철학, 담담한 톤)

**1) 공학적 문제 해결 마인드**
공학적으로 문제를 파악·분석·해결한다.
시험과 데이터로 증명한다.

**2) 사람의 편리함을 제공하는 마인드**
소비자 니즈를 읽고 분석한다.
해결책을 제시한다.

**왜 두 개를 같이 하는가.**

자동화의 끝에는 인간이 직접 하고 있는 1차 산업과 노동이 남는다.
그 노동을 해결하는 기업이 진짜 리더가 될 것이다.

농업 자율주행(SS500)은 그 시작점이다.
AI 워크플로우는 그 자동화의 공학적 훈련이다.

두 축이 만나는 지점에서 나는 일한다.
