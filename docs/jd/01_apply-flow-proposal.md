# 공고 수집에서 지원서 제출까지: 이상적인 흐름 제안 (t265)

> 작성 2026-10-14. 제안 + 최소 구현 현황. 제출 버튼은 항상 운영자가 누른다.

## 문제

수집(Wanted·해외 ATS·자소설)과 텔레그램 알림은 되지만, 알림을 본 뒤에 이력서·커버레터·폼 답변을 매번 손으로 새로 쓰고 폼에 옮겨 적어야 한다. 병목은 수집이 아니라 "한 건을 끝까지 넣어보는 일"이다.

## 목표 흐름 (5단계)

| 단계 | 하는 일 | 지금 상태 |
|---|---|---|
| 1. 일일 후보 | 수집 공고를 적합도 순으로 상위 N건 + 이유(도메인 일치, 근거 이력 줄 수, 폼 로그인 여부, 열림 확인) | **구현** `apply_flow.py shortlist --check-open` |
| 2. 지원 준비 | 한 건을 골라 키트 생성: 이력서 변형, 커버레터 KR/EN, 폼 답변, 포트폴리오 링크 | **구현** `apply_flow.py kit <키>` (프로필 원문 인용만, 빈 곳은 `[TODO]`) |
| 3. 제출 보조 | 자동화 Chrome에서 폼을 열어 알려진 칸을 채우고 **제출 직전에 멈춤**, 스크린샷 | **구현** `apply_browser.py` (로그인 벽은 `blocked-login`으로 보고) |
| 4. 운영자 제출 | 운영자가 화면을 확인하고 제출 클릭 | 사람 |
| 5. 추적 | 지원/회신/면접을 원장에 기록(날짜별 history) | **구현** `apply_flow.py track <키> <상태>` |

## 설계 결정

- **발명 금지**: 키트의 모든 문장은 `RESUME.md`(국문 마스터)와 `apple/materials/resume_en.md`(영문)의 원문 줄이다. 줄마다 출처를 붙이고, 프로필에 없는 것(지원 동기, 연봉, 근로허가, 이주 의사)은 `[TODO: 운영자 입력]`로 남긴다.
- **적합도 = 기존 shortlist 게이트 + 도메인 가감점**: 기존 `shortlist.py`는 제목만 보므로 React QA 공고가 모터제어 공고보다 위로 오는 일이 있었다. 프로필이 깊은 도메인(모터·BLDC·임베디드·CAN·양산·신뢰성·시험)은 가점, 기록이 없는 도메인(React·Spring·모바일 앱·영업)은 감점한다.
- **열림 확인**: Wanted는 닫힌 공고도 HTTP 200이라 JSON `status`로 판정, Greenhouse/Lever/Ashby/Workday는 공개 API로 확인.
- **채팅 알림은 후보 리스트 1통**으로 충분하다(이번 범위에서는 알림 연결 안 함).

## 한계와 다음 단계

1. **Wanted·Workday·자소설은 지원 시 로그인이 필요**하고 `hih login`에 저장된 계정이 없다. 이번 실제 실행(도울로보틱스 `wanted:383727`)은 폼 앞 로그인 벽에서 멈췄다(증거: `docs/jd/wanted-383727/attachments/`). 운영자가 `hih login set-secret`으로 wanted 계정을 등록하면 3단계가 그대로 이어진다.
2. 해외 ATS(Greenhouse/Lever/Ashby)는 로그인 없이 폼이 열리지만 현재 수집분 중 한국에서 지원 가능한 적합 공고가 0건이다(근로허가 게이트).
3. 후보 점수는 규칙 기반이다. 쓰임이 확인되면 키트 문장 다듬기를 모델 호출로 바꿀 수 있다(그때도 프로필 원문 인용 제약 유지).
4. 후보 알림(텔레그램)과 "지원 준비" 한 번 탭은 3단계 로그인 해결 후 붙인다.
