[p3 AX Product Engineer 소개]

point3의 AI 업무 체계를 처음부터 함께 만듭니다
• 사람들이 실제로 일하는 방식을 바꾸고자 합니다.
• 회의, 문서, Slack, Linear, 코드와 각자의 머릿속에 흩어져 있는 정보를 찾고 논의를 실행으로 옮기는 과정에는 여전히 많은 수작업들이 필요합니다.
• 개인이 쌓은 판단과 경험도 조직이 계속 활용할 수 있는 기억으로 충분히 남지 않습니다.
• AX Product Engineer는 이 문제를 처음부터 풀어갈 point3의 첫 AX 전담자입니다. CEO, Tech Lead, 실제 사용자들과 가까이 일하며 현업의 문제를 발견하고, 조직의 맥락을 AI가 활용할 수 있는 구조로 연결하고, 사람들이 반복해서 사용하는 내부 제품으로 만듭니다.
• 완성된 시스템을 운영하는 자리가 아닙니다. AI가 point3에서 일하는 기본 인터페이스가 되도록 회사의 업무체계를 0에서부터 설계하는 자리입니다.

만들고 싶은 변화
• 구성원이 정보를 찾고 문서를 만들고 후속 업무를 실행할 때, 여러 시스템을 일일이 오가는 것보다 AI를 먼저 사용할 수 있어야 합니다.
• 회의에서 나온 결정은 담당자와 다음 행동으로 자연스럽게 이어지고, 문서와 대화, 코드와 업무 기록은 서로 연결되어야 합니다. 한 사람이 알고 있던 맥락과 판단은 사라지지 않고 조직의 기억으로 축적되어 다음 업무와 의사결정에 다시 쓰여야 합니다.
• 만들어낸 기능의 수보다 실제 행동의 변화에 집중합니다. 핵심 업무에서 새로운 방식이 기존 수작업들보다 먼저 선택되고 반복 사용될 때, AX가 작동한다고 판단합니다.

## 주요업무

합류하면 함께 할 일

 - 현업에서 AX 기회들을 발견합니다
• 10명의 구성원과 밀착해 실제 업무를 관찰 및 인터뷰합니다.
• 반복 작업, 정보 단절, 의사결정 병목들과 사람에게만 묶인 정보들을 찾아냅니다.
• 기술을 먼저 정하지 않고 문제의 중요도, 반복성, 기대 효과와 검증 비용을 기준으로 우선 순위를 세웁니다.
• point3의 AX 기회지도를 만들고 가장 가치 있는 문제부터 작게 검증합니다.

 - 조직의 맥락을 AI가 활용할 수 있게 만듭니다
• 회의와 대화 기록, 문서와 파일, Slack, Linear, 코드와 개발 기록을 연결합니다.
• 단순한 통합 검색을 넘어 사람, 업무, 결정, 근거와 후속 행동의 관계를 보존합니다.
• 구성원의 경험과 판단 기준을 재사용할 수 있는 지식과 업무 흐름으로 구조화합니다.
• 모델이 필요한 맥락을 정확히 찾고 출처를 확인하며 실제 업무 도구를 사용할 수 있도록 검색, 메모리와 도구 호출 구조를 설계합니다.

 - 내부 AX 제품을 직접 만듭니다
• 조직 지식 검색, 회의에서 실행으로 이어지는 자동화, 특정 업무를 끝까지 수행하는 에이전트 등을 만듭니다.
• AI 백엔드, 컨텍스트 파이프라인, 데이터·지식 구조와 에이전트 워크플로를 직접 설계하고 구현합니다.
• 화려한 데모보다 가장 작은 작동 제품을 빠르게 만들어 실제 업무에서 검증합니다.
• 특정 언어나 프레임워크에 맞추기보다 문제에 가장 적합한 도구를 선택합니다.

 - 만든 제품을 실제 업무 방식으로 정착시킵니다
• 배포에서 멈추지 않고 사용 장면을 관찰하며 제품을 반복 개선합니다.
• 사용자가 기존 방식으로 돌아가는 이유를 확인하고 정확도, 속도와 사용 흐름을 고칩니다.
• CEO, Tech Lead와 실제 사용자로 구성된 스쿼드와 함께 새로운 업무 방식의 도입을 이끕니다.
• 빠르게 실험하되 합의된 범위, 접근권한과 감사 가능성이라는 최소 안전 원칙을 지킵니다.

## 자격요건

이런 분을 찾습니다

• 현업의 말만 듣지 않고 실제 업무를 관찰해 해결할 가치가 있는 문제를 찾아내는 분
• 모호한 문제를 작고 검증 가능한 제품으로 정의하고 구현과 배포까지 직접 수행해 본 분
• 조직의 문서, 대화와 업무 데이터를 AI가 활용할 수 있도록 검색, RAG, 메모리, 지식 구조 또는 컨텍스트 파이프라인을 설계해 본 분
• LLM이 외부 도구와 업무 시스템을 사용해 여러 단계의 작업을 수행하는 구조를 설계하거나 운영해 본 분
• 특정 기술을 먼저 도입하기보다 문제와 제약을 이해한 뒤 적절한 접근법을 선택하는 분
• 제품 출시를 끝으로 보지 않고 실제 반복 사용과 업무 행동의 변화를 확인하며 개선하는 분
• 정해진 요구사항을 기다리기보다 스스로 판단 기준을 만들고 결과까지 책임질 수 있는 분

연차, 학력, 특정 언어와 프레임워크, 핀테크 경험을 일률적으로 요구하지 않습니다. 대신 어떤 문제를 왜 선택했고, 무엇을 깊이 연구했으며, 실제 사용자와 조직에 어떤 변화를 만들었는지를 봅니다.



이런 환경에서 일할 수 있어야 합니다
• 처음부터 정리된 데이터나 확정된 백로그가 주어지지 않습니다. 첫 AX 전담자로서 무엇을 하지 않을지 결정하고 가장 중요한 문제에 집중해야 합니다.
• 좋은 모델이나 멋진 데모만으로는 부족합니다. 서로 다른 도구에 흩어진 맥락을 연결하고, 실제 사용자가 기존 습관을 바꿀 만큼 유용한 제품을 만들어야 합니다. 빠른 성과를 내면서 다음 제품에서도 재사용할 수 있는 기반도 함께 남겨야 합니다.
• 이 어렵고 밀도 높은 문제를 즐기고, 중요하다고 판단한 일에는 연구와 노력을 아끼지 않는 분과 함께하고 싶습니다.

## 우대사항

이런 경험이 있다면 좋습니다
• 사내 문서, 대화와 업무 시스템을 연결한 검색 또는 지식 플랫폼을 실제 환경에서 구축·운영한 경험
• RAG, 지식 그래프, 에이전트 메모리 또는 검색 품질 평가를 제품에 적용하고 개선한 경험
• LangGraph, CrewAI, AutoGen 등 상태 기반 에이전트 프레임워크를 깊이 사용하거나 분석한 경험
• Neo4j 등 Graph DB로 지식과 업무 관계를 모델링한 경험
• MCP 또는 유사한 도구 호출 구조로 AI와 실제 업무 시스템을 연결한 경험
• 작은 조직에서 문제 발견부터 제품 구현, 배포와 운영까지 넓은 범위를 책임진 경험
• 중요한 문제를 논문, 코드, 기존 제품과 사용자 관찰까지 파고들어 자기 기준을 만든 경험
