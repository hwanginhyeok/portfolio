## What to add

### 1. `--html` flag on `scripts/wanted_collect.py`
Renders a self-contained HTML report of THAT DAY'S NEW postings to
`docs/jd/_inbox/wanted/report/YYYY-MM-DD.html` (create the directory).
Not all 271 — only what the run newly wrote, the same set the markdown digest lists.
If the run found zero new postings, still render the report saying so, including the
watchlist table. A quiet day must still produce a valid file.

### 2. `--telegram` flag
Sends the rendered HTML file to the PM secretary bot as a Telegram document.

Credentials: read `PM_BOT_TOKEN` and `PM_BOT_CHAT_ID` from `/home/window11/project-manager/.env`
(KEY=VALUE lines). Both keys are confirmed present. Never print, log, or commit their values.
`--telegram` implies `--html` — refuse to send without a rendered file.
If credentials are missing, print a warning and exit 0 (collection already succeeded; a failed
send must not mark the whole run failed).

Send with `sendDocument` via stdlib `urllib` multipart POST. The exact working pattern lives in
`/home/window11/sns-studio/scripts/studio_dashboard.py` (functions `telegram_creds` and
`send_document`) — read it and copy the multipart construction. Do not add a `requests`
dependency for this; `urllib` is what the precedent uses.
`chat_id` goes in the form body as a string — that is correct for sendDocument.

Caption (plain text, under 1000 chars):
```
📋 원티드 채용 리포트 YYYY-MM-DD
신규 N건 (핵심 M건) · 누적 T건
⚠️ 워치리스트: <0이 아닌 기업이 있으면 여기 명시, 없으면 "대기업 신규 없음">
```

### 3. The HTML itself — this is the actual deliverable the user reads

The user opens this on a phone from Telegram. Design for that.

Requirements:
- **Self-contained.** No external CSS, JS, fonts, or images. Inline everything. It must render
  correctly with no network.
- **Mobile-first.** Single column, comfortable tap targets, no horizontal page scroll.
  Any wide element gets its own `overflow-x: auto` container.
- **Light and dark.** Define the light palette on bare `:root`, then override the same tokens
  inside `@media (prefers-color-scheme: dark)`. Give `body` an explicit background token —
  never leave it transparent.
- **Watchlist first.** A table of the conglomerate watchlist and their Wanted posting counts.
  When every count is 0, render it as one quiet muted line — it must not dominate the page.
  When ANY count is non-zero, render a loud banner at the very top naming that company, before
  everything else. That is the single most important event this report can carry.
- **Core-first ordering.** Rank the new postings so the relevant ones come first. Treat a
  posting as "핵심" when its position title matches manufacturing / AI / PM / engineering
  intent (제조, 자율, 스마트팩토리, 생산, 공정, 설비, PM, 프로젝트 매니저, Product Manager,
  프로덕트, 하드웨어, 전장, 임베디드, 기구, 로봇, 모빌리티, Technical Project). Show 핵심
  as full cards at the top. Put the rest in a collapsed `<details>` section below, labelled
  with its count.
- **Card contents** per posting: 회사명, 포지션, 지역(시/구 수준으로 축약 — full street
  addresses are noise on a phone), skill tags as small chips (cap at ~8, then "+N"),
  a 2–3 line excerpt of 자격요건, and a link to `https://www.wanted.co.kr/wd/<id>`.
  Escape all text — company and position strings contain quotes, angle brackets and emoji.
- **Header**: date, 신규 N건, 핵심 M건, 누적 T건.
- Korean UI text throughout.

Keep the whole page under ~500KB. If a day ever brings a huge batch, cap the non-핵심 cards at
100 and say how many were omitted — never truncate silently.
