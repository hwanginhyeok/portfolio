제품 개발 행이 7단계 전부 채워진다 — "끝까지 간다"를 한눈에.

T1 현장 설계

현장에서 돌아오는 설계

DFMEA는 문서가 아니다. 고장모드를 먼저 상상하고, 설계로 돌아가는 사고방식이다.

현장에서 사고가 나기 전에 Boundary Diagram에서 그 고장을 잡는다. AIAG-VDA 7-step — 근본원인 → 설계변경 → 검증.

Step 1

계획·준비

Planning & Preparation

범위
무엇을 볼 것인가
하는 일 분석 범위·경계·일정과 역할을 정한다. 무엇을 분석하고 무엇을 하지 않는지 먼저 적는다.
도구 Scope 정의서 · 이전 FMEA·현장 이력 수집
Step 2

구조 분석

Structure Analysis

경계
요소와 인터페이스
하는 일 시스템을 요소로 나누고 인터페이스를 그린다. FM 배치 규칙을 먼저 세운다.
도구 Boundary Diagram · Structure Tree · Assembly 단위 재편
Step 3

기능 분석

Function Analysis

기능
요구와 연결
하는 일 각 요소가 해야 하는 기능과 요구조건을 연결한다. 시험 항목으로 이어질 수 있는 문장으로 쓴다.
도구 Function Net · 요구조건 ↔ 시험 항목 매핑
Step 4

고장 분석

Failure Analysis

FM→FE→FC
고장 사슬
하는 일 고장모드(FM) · 영향(FE) · 원인(FC)을 사슬로 잇는다. 현장에서 돌아온 문제는 근본원인까지 파서 여기에 환류한다.
도구 Failure Net · 근본원인 분석(5-Why) · 재현 시험
Step 5

리스크 분석

Risk Analysis

AP
조치 우선순위
하는 일 심각도·발생도·검출도로 평가하고, 공식 우선순위는 Action Priority(AP)로 판정한다. S×O 뷰는 보조 지표로만 쓴다.
도구 S/O/D 평가표 · AP 표 · DFMEA 스크리닝 뷰
Step 6

최적화

Optimization

조치
설계 변경·검증
하는 일 높은 우선순위 항목에 설계 변경 또는 시험 추가를 배정하고, 조치 후 재평가한다.
도구 조치 추적표 · 재평가 · 후속 태스크 관리
Step 7

결과 문서화

Results Documentation

문서
양산 게이트로 인계
하는 일 결론과 남은 위험을 문서로 남겨 다음 개발과 양산 게이트에 넘긴다.
도구 DFMEA 보고서 · APQP 게이트 체크리스트 연계
T2 시험 증명

기획에서 양산까지 — 시험으로 증명한다

시험은 몇 개 만들었는가가 아니다. 매번 어떻게 접근하는가가 역량이다.

가설 → 장비 설계 → 데이터 → 결정. 장비가 없으면 만든다.

정지 후 전원 차단 시퀀스를 재설계

01 기획 / Plan

어떤 가설을 세우는가?

  • "PWM 절환 방식이 소자 발열을 낮추는가?"
  • "접촉 정지거리는 이론 모델과 얼마나 다른가?"
  • "구조 변경이 풍속 분포에 미치는 영향은?"
02 설계 / Design

장비가 없으면 만든다

  • 다이나모미터 토크제어 시스템 — 스트레인 게이지 브리지 + 다점 교정
  • 유체·송풍·접촉 시험 벤치 직접 구축
  • CAN 정합성 체크리스트 — 반복 검증 프로토콜 표준화
03 증명 / Prove

데이터로 답한다

  • 조건 매트릭스 × 반복 × 통제변수 고정
  • 오실로스코프 · 실시간 로깅으로 동시 계측
  • 사내 벤치 → 외부 시험기관의 계층적 검증
04 분석 / Analyze

데이터가 말하는 것 → 다음 결정

  • 판정 기준과 대조해 채택/보류를 결정
  • 비용·운전시간 트레이드오프까지 정량화
  • 조건부 판정은 해제 조건과 함께 기록

대학원 "모델→시뮬레이션→실험 검증" 체질이 실무 "기획→설계→증명→분석"으로 이어진다.
