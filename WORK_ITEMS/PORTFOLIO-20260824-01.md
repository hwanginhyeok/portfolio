# PORTFOLIO-20260824-01 — Durable job-collector state and deterministic shortlist repair

## Context

The Wanted dedup ledger at `docs/jd/_inbox/wanted/state.json` was zero bytes
after an ENOSPC event. Both collectors persisted JSON directly with
`Path.write_text`, which can truncate the target before the write fails. The
global collector used the same unsafe persistence pattern. Existing posting
files and digest artifacts had to remain untouched.

## Scope and ownership

Owned files: `scripts/`, focused tests, the repaired Wanted ledger, and the
required project handoff records. Pre-existing dirty/untracked user artifacts
were not edited or deleted. Runtime V2 lifecycle state was out of scope.

## Diagnosis

The failure was reproduced locally in a temporary directory: a simulated
`OSError(28, "No space left on device")` after opening a target for writing
left the previous valid JSON file at 0 bytes. The real Wanted state reproduced
the same symptom and exited from `load_state` with a JSON parse error.

## Implementation

- Added `scripts/state_utils.py` with same-directory temporary JSON writes,
  flush, file fsync, atomic `os.replace`, best-effort directory fsync, and
  cleanup on success or failure.
- Replaced direct state writes in both collectors and fail the run before
  report/digest continuation when state persistence fails.
- Added `scripts/wanted_state_repair.py`. It reads the committed `HEAD` ledger,
  merges local Wanted frontmatter and digest rows without overwriting baseline
  values, keeps IDs for zero-byte files, and writes only through the atomic
  helper. The repaired ledger has 327 entries: 299 baseline and 28 additions.
- Added `scripts/shortlist.py` for deterministic feasibility gates and fit
  ranking. ITAR is always blocked; ordinary visa-needed, US-only remote,
  unclear remote scope, unconfirmed sponsorship, generic sales/marketing/CX,
  and profile-outside roles remain informational. Korea, explicit
  worldwide/Korea/APAC remote, and credible sponsorship roles can be
  actionable when profile evidence exists; non-Korea APAC requires affirmative
  sponsorship evidence and no anti-sponsorship clause.
- Added a strict owner-domain gate: title/department fit must also name
  automotive/mobility, motor/power-electronics, embedded/electrical hardware,
  robotics/industrial automation, machinery/equipment,
  physical-product test/validation/reliability/quality, or technical product
  industrialization. Consumer beauty/fashion/food/e-commerce, OEM production
  management, SCM/sourcing-only, generic software/AI, unrelated managers,
  sales/CX/marketing, and body-only matches remain informational.
- Updated Wanted and global HTML/Markdown reporting to retain raw collection
  while separating actionable high-fit roles from informational/ineligible
  roles.

## Rejected PM-661 continuation

- Tightened `scripts/shortlist.py` so actionable fit evidence comes only from
  the title or department. Body-only keyword matches remain informational, and
  a minimum profile gate requires both a concrete manufacturing/process,
  test/validation, reliability, quality/supplier, NPI, or electrical/hardware
  fit and a credible owner-domain connection. A bare technical-program title
  is not sufficient.
- Added explicit exclusions for Order Management, sales, CX, marketing, generic
  AI/software roles, and unrelated manager roles. Physical-product AI/software
  roles remain eligible only when the physical domain is named in the title or
  department. The regression corpus now keeps the beauty OEM production
  manager, materials sourcing/production manager, and generic SCM production
  management roles informational while retaining Aptiv Manufacturing
  Engineering Engineer and Test Lab Engineer.
- Made feasibility conservative: ITAR/U.S.-person evidence blocks first;
  visa-needed is excluded; sponsorship requires affirmative credible text; and
  remote requires a role-level worldwide/Korea/APAC scope. Incidental phrases
  such as `Remote Pilot Certificate` and company-wide `worldwide` boilerplate
  do not create remote eligibility.
- Added `--hydrate-zero-byte` to `scripts/wanted_state_repair.py`. It performs
  only bounded Wanted detail GETs for files that are exactly zero bytes, uses
  atomic text writes, refuses to overwrite a target that changed, and prints a
  per-ID receipt. The authorized run targeted 16 files and completed 16/16.
- Hydration success IDs were `110132`, `350510`, `361079`, `361330`, `370445`,
  `370706`, `378719`, `379130`, `380499`, `380543`, `381187`, `381554`,
  `381602`, `381666`, `381759`, and `381814`; failure and skipped IDs were
  empty.
- Kept raw collection and report decks intact; only the 16 zero-byte Wanted JDs
  were filled. No normal collector, Telegram, publication, email, credential,
  paid service, commit, push, deploy, or cron action was performed.

- Updated the global actionable count to use the shortlist classifier rather
  than the raw eligibility bucket count. Wanted and global raw collections,
  owner-domain gates, Korea precedence, ITAR/U.S.-person precedence,
  visa-needed handling, and remote-scope handling remain intact.
- Added focused regressions for APAC without sponsorship, APAC with explicit

## Limitations

The 16 local Wanted JD files that were zero bytes are now hydrated. Their
first-seen values remain blank where no local date evidence existed; no date
was invented. A full scheduled collector run remains intentionally unperformed
because the bounded detail-read run was sufficient for this task. The final
owner-domain verification used no network and wrote no JD or state artifact.
Telegram, publication, credentials, paid services, commit, push, deployment,
and cron changes were not performed.
